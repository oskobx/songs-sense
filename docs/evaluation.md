# Vibe Search evaluation — method and results

Detail behind the summary in the [README](../README.md). The design spec that
preceded this work is [vibe_eval_spec.md](vibe_eval_spec.md); this document
records what was actually built and what it measured.

## Query set

114 curated queries: 81 en, 19 pl, 9 de, 5 es. Deliberately over-weighted toward
non-English relative to the corpus (79/8.7/5.6/4.0) because the language-routing
and boost mechanism is the part most likely to be broken.

Queries were generated by an LLM across five categories — emotional states,
situations, abstract vibes, sensory images, relational — then curated by hand
with a keep/delete CLI, over-generating ~140 so ~114 survived. Deletions were
near-duplicates, disguised song titles, queries too vague to have an answer, and
queries too specific to be a vibe.

The generator never sees corpus content. Generating queries *from* songs — pick a
song, describe it, use the description as the query — guarantees a perfect match
exists for every query and inflates every metric.

## Judge

`openai/gpt-oss-120b` via Groq grades each (query, passage) pair 0–3 on how well
the passage delivers the feeling the query describes. Judgments are cached on
`(query_id, passage_id)`, namespaced by model and prompt version, so re-running
against unchanged retrieval costs almost nothing and a prompt change never mixes
two judges' opinions in one results file.

Three prompt versions, each measured against the same 30-pair tuning batch:

| Version | Kappa (tuning batch) | What changed |
|---|---|---|
| v1 | 0.243 | Original. Rewarded topical and lexical adjacency — graded 2 where the human graded 1 on 10 of 30 pairs, matching a shared noun rather than a shared feeling. |
| v2 | 0.100 | Made the 1-vs-2 boundary explicit and named surface-feature overlap as insufficient. Fixed the intended problem — "relevant" count fell from 20/30 to 11/30 against the human's 10/30 — but collapsed the top of the scale, awarding grade 3 to **zero** of 30 pairs. |
| v3 | 0.213 | Kept v2's rule, repaired the ceiling by stating that 3 is expected when a passage lands the feeling. 3s returned (4/30). |

A useful diagnostic along the way: no monotone rescaling of v1's output could
exceed kappa 0.265, which established early that the disagreement was about
*which* passages were relevant, not about where to put a threshold. Prompt
wording could fix that; a calibration curve could not.

## Calibration

55 hand-graded pairs, sampled across three rank bands — ranks 1–3, 4–10, and
15–30 — so the set contains genuine 0s and 1s. Sampling only top hits produces a
calibration set with almost no low grades and a meaningless kappa.

Restricted to en/pl: a grader who cannot read a language cannot produce a
trustworthy grade in it. The cost is that the kappa validates the judge on those
two languages only.

Split into two batches drawn from **disjoint queries**:

- **Batch 1** (30 pairs) — the tuning set. Three prompt revisions were measured
  against it.
- **Batch 2** (25 pairs) — held out, scored once, after v3 was final.

Batch 1 was then re-graded blind: same pairs, fresh random order, original
grades never displayed, written to a separate field so the originals survive.

| Comparison | Statistic | Value | n |
|---|---|---|---|
| Judge v3 vs human, held-out batch 2 | quadratic-weighted kappa | 0.460 | 25 |
| Judge v3 vs human, batch 1 (re-graded) | quadratic-weighted kappa | 0.340 | 30 |
| Judge v3 vs human, batch 1 (original) | quadratic-weighted kappa | 0.213 | 30 |
| Human vs self, blind re-grade | quadratic-weighted kappa | 0.418 | 30 |
| Judge vs self, repeated calls | exact-repeat rate | 0.88 | 50 |

Quadratic weighting because the grades are ordinal: confusing 3 with 2 should
cost far less than confusing 3 with 0.

### What the re-grade showed

The grader's standard shifted between sessions. Zeros fell from 20% of pairs to
8%, and the "relevant" rate rose from 33% to 44%. The round-2 distribution
matched batch 2's almost exactly (mean 1.50 vs 1.44) and diverged from batch 1's
first pass (1.23) — two independent sessions under a settled standard agreeing
with each other, with the first session as the outlier.

That is why the judge scores better against the re-graded batch 1 (0.340) than
against the original grades (0.213): the target got more consistent, not the
judge.

### The ceiling

Human self-agreement is 0.418. Held-out judge agreement is 0.460 — on different
pairs, so not a clean comparison; on the same pairs the judge reaches 0.340,
about 81% of the ceiling.

Either way the conclusion holds: **the remaining gap is mostly grader noise, not
judge error.** Exact self-agreement was 10/30 — a different grade on two-thirds
of pairs the second time. Further prompt tuning against a target this noisy
fits noise. If the absolute numbers need to mean more, the lever is the grading
protocol — averaging both rounds, or writing an explicit rubric before grading —
not the judge.

Worth stating plainly: n=30 and n=25 give wide confidence intervals on every
kappa above.

## Metrics

Computed over the top 10 per query, with "relevant" meaning grade ≥ 2.

- **recall@k** — fraction of queries with at least one relevant result in the
  top k.
- **MRR** — 1 / rank of the first relevant result, averaged.
- **NDCG@10** — exponential gain, `(2^grade − 1) / log2(rank + 1)`, with IDCG
  taken over the grades observed for that query. That is the standard practical
  approximation when the corpus is not exhaustively labelled, and it flatters
  queries whose best available result is mediocre.

Baseline (judge v3, semantic-only retrieval, +0.1 language boost, no reranker,
8-line chunks):

| Slice | n | recall@1 | recall@5 | recall@10 | MRR | NDCG@10 |
|---|---|---|---|---|---|---|
| Overall | 114 | 0.50 | 0.82 | 0.89 | 0.63 | 0.80 |
| en | 81 | 0.48 | 0.84 | 0.90 | 0.63 | 0.81 |
| pl | 19 | 0.53 | 0.74 | 0.84 | 0.62 | 0.78 |
| de | 9 | 0.44 | 0.67 | 0.78 | 0.57 | 0.73 |
| es | 5 | 0.80 | 1.00 | 1.00 | 0.90 | 0.88 |

## What the eval caught

**Spanish was silently mis-routed.** `lingua` was built with English, Polish and
German only, so all five Spanish queries were detected as `en` or `pl`, embedded
with the English-only model, and given a boost toward the wrong language. Adding
Spanish to the detector and the multilingual routing set moved es from MRR 0.46 /
NDCG 0.71 / recall@1 0.20 to 0.90 / 0.88 / 0.80, and overall MRR from 0.61 to
0.63. Detection now matches the declared language on all 114 queries.

**The judge fabricated grades on unparseable responses.** An earlier version
cached 0 when a response could not be parsed — indistinguishable from a genuine
"not relevant", and therefore permanent and invisible. All 233 affected cache
entries were deleted and re-judged with a larger token budget; 93 came back
non-zero. A control re-judging 50 known-non-zero entries showed 26% baseline
churn from judge nondeterminism, so roughly 30 of the 93 were real repairs and
the rest noise. Individual entries cannot be attributed. The judge now escalates
the token budget and then raises rather than inventing a grade.

## Running it

```bash
python -m src.eval.generate_vibe_queries            # LLM-generated candidates
python -m src.eval.curate_queries                   # keep/delete CLI
python -m src.eval.grade_calibration                # sample + grade 30 pairs
python -m src.eval.grade_calibration --add 25       # a held-out batch
python -m src.eval.grade_calibration --regrade 1    # blind re-grade
python -m src.eval.calibrate --versions v3 --self-consistency 10
python -m src.eval.run_vibe_eval --note "what changed"
```

`run_vibe_eval` writes `data/eval/results_<timestamp>.json` with per-query detail
and the retrieval config, so runs stay comparable across changes. Needs
`GROQ_KEY` in `.env` and a populated local Postgres.

Lyric excerpts in the committed eval artifacts are truncated to two lines plus an
ellipsis; the full passages exist only in the database.
